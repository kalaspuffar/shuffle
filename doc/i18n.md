# Shuffle — Adding a Language (for community contributors)

Shuffle's interface is fully i18n-ready: **every user-visible string lives in
`include/lang/en.json`** (zero hardcoded strings in the codebase, enforced by
`MAINT-04`). Adding a new language does **not** touch a single PHP or JS file —
one new file is the entire change.

## The one-file addition

```bash
cp include/lang/sv.json include/lang/{your-code}.json
```

`{your-code}` is the [ISO 639-1](https://en.wikipedia.org/wiki/List_of_ISO_639-1_codes)
code, two or three lowercase letters (optionally `_REGION`, e.g. `zh_Hans`) —
the same format the setup wizard's app locale uses. Then translate the values.
You are done — no code, no config, no restart, no migration.

## What the app does with your file

1. **Discovery** — at boot, every `include/lang/{code}.json` that exists and
   parses as a JSON object is listed. Nothing else needs registering.
2. **Selector** — it appears automatically in **Profile → Appearance →
   Language**, labelled by its own name. Add this key to make the label
   correct:

   ```json
   "{your-code}.__native_name": "日本語"
   ```

   (Omitting it is safe: the option then displays the bare code. The
   `__native_name` values are metadata for the selector — they are never
   rendered by `t()`-like lookups.)
3. **Per-key English fallback** — your file sits *over* `en.json`. Any key you
   **omit** falls back to the **English** string: the user sees the English
   sentence, not a key name, not a "missing translation" error, nothing broken.
   A partial translation is therefore safe to ship and safe to grow — translate
   what you can, the rest reads fine in English until you add it.
   (Keys only in `en.json` are never lost: `en.json` remains the authoritative
   source of truth and always loads.)
4. **Placeholders** — keep the `{0}`, `{1}`, … tokens **exactly as they are**
   (positions may of course move as the language requires, e.g. Japanese word
   order), and keep the same *set* of per-key tokens. Example:

   ```json
   "en":  "assigned {0} to you.",
   "sv":  "tilldelade {0} till dig."
   ```

## Complete = recommended

`include/lang/sv.json` is the shipped reference: it translates **every** key of
`en.json` and is the template to copy from. The repository's test suite
(`tests/e2e-i18n.php` §4) machine-checks that completeness and placeholder
parity are never violated for the files it knows about.

## Checklist before you open a PR

- [ ] File name is a valid locale code (matches `^[a-z]{2,3}(_[A-Z]{2})?.json$`).
- [ ] Valid JSON, `"{code}.__native_name"` present.
- [ ] `{N}` tokens preserved per key, same set as `en.json`.
- [ ] No stray non-Latin / wrong-script characters slipped in (happens to the
      best of us; a quick `grep -P '[\x{0400}-\x{04ff}\x{0600}-\x{06ff}]'` is
      worth a look).
- [ ] `php tests/e2e-i18n.php` + `bash tests/http-i18n.sh` stay green (they
      cover `en`/`sv`; your file is picked up automatically if added).

That's the whole surface. Thank you for contributing a language 🌍
